# SysML v2

SysML v2 のテキスト表記(`.sysml`)から、規格の図表記に沿った図と表を作るブラウザアプリです。
`index.html` 1 ファイルだけで動き、サーバーにデータを送らず、ネットなしで動きます。

ハッカソンの講義で、Arduino 複数台からなるシステムを説明・設計するために作りました。生成 AI にテキストを書かせ、アプリに貼って図にする使い方を主としています。

- 1 つのシステムを表す 1 つのテキストから、すべての図と表を作る
- 入力は SysML v2(SysML 2.0 正式版)の正規のテキスト表記で、独自の記法はない
- 一般ビュー・相互接続ビュー・アクションフロービュー・状態遷移ビュー・シーケンスビューの 5 つの図と、グリッドビュー(4 つの表)を、画面で切り替えて見る
- 構文エラー・意味エラー・警告・未検査を診断に出し、生成 AI に渡す修正依頼の文としてコピーできる
- 図の要素を選んで、名前の変更、部品・ポート・接続の追加、削除ができ、テキストが書き換わる
- フォルダの中の複数の `.sysml` を、1 つのモデルとして扱える
- 図と表は 1 つずつ SVG・PNG・PDF で保存でき、表はタブ区切りでコピーできる

## 使い方

公開版は https://sysmlv2.sapp.jp で使えます。
`index.html` をブラウザで直接(`file://` で)開いても使えます。

1. 公開版か `index.html` を、ブラウザで開きます。
2. 左のテキスト欄に SysML v2 のテキストを書きます(貼り付けてもかまいません)。右に図が出ます。書き方は、上の帯の「書き方」で見られます。
3. 上の帯の「ビュー」で、図の種類を切り替えます。「範囲」で、描く範囲を選びます。
4. 図の要素をクリックすると、テキストの該当箇所が選ばれ、図の下の編集欄に、その要素の操作が出ます(下の「図から編集する」)。

上の帯には、アプリ名、「新規」「開く」「保存」、「ビュー」と「範囲」の選択欄、表示の設定、「例を読み込む」「書き方」が並びます。左にテキスト欄とその下の診断欄、右に図、その下に選んだ要素の編集欄があり、間の分割バーで幅を変えられます。

- 「新規」は、空のパッケージの骨組み(`package '新しいシステム' {` と `}` の 2 行)を入れます。一般ビューでその外枠を選べば、「部品を足す」から始められます。
- 「例を読み込む」では、入門用の短い例(電池・スイッチ・ランプの回路)と、機能紹介用の例(見守りシステム)のどちらかを選べます。
- テキストに構文エラーがある間は、最後に正しく描けた図を薄く表示し、図からの編集を止めます。

## 生成 AI で書かせる

入力がテキストなので、生成 AI が書いたテキストをそのまま貼るだけで図になります。

ChatGPT・Claude などの生成 AI に書いてもらうときは、最初に `docs/prompt_for_ai.md` の指示文を渡してください。アプリの「書き方」の「生成 AI 向けプロンプト」の「コピー」で写す文と同じものです。

1. 指示文をコピーし、最後の「システム:」の後ろに、作りたいシステムの説明を書き足して、生成 AI に渡す
2. 返ってきたテキストを、左のテキスト欄に貼る
3. 診断欄にエラーや警告が出たら、「修正依頼をコピー」を押して、生成 AI に渡す。修正依頼では、構文エラー・意味エラーは直すもの、警告は意図の確認事項として扱わせる(書き間違いと判断できるものだけ直し、判断できないものは変えずに、確かめたいことを質問として挙げる)

どんな形のテキストが返ればよいかは、「例を読み込む」の入門用の例が短い手本になります。

## 書き方

SysML 2.0 正式版のテキスト表記を、そのまま書きます。日本語の名前は単一引用符で囲みます(図では引用符を外して表示します)。引用符なしの名前は、英字・数字・`_` だけです。

次は、アプリの「書き方」の例から抜き出した部分です(これだけでは 1 つのモデルになりません)。

```
part def 'Arduino Uno' {
    in port 'A0';
    out port 'D8';
}
part '測定ボード' : 'Arduino Uno';
connect '出力ボード'.'D3' to '冷却ファン'.'制御';
flow of '電圧値' from '温度計'.'出力' to '測定ボード'.'A0';
view '全体図' {
    expose '見守りシステム';
    expose '見守りシステム'::**;
}
```

部品・ポート・接続・インターフェース・フロー・結合、図にする範囲(`view`・`expose`・`filter`)、定義と使用・特殊化、要求と `satisfy`、ユースケースと行為者、計算・制約、状態と遷移、手順(`action`・`first`・`then`)と分岐・並行、部品が行う行動(`perform`)、やりとり(`occurrence def`・`message`)、注、ファイルに分けるときの決まりの書き方の例は、アプリの「書き方」に一覧があります。

## ビュー

図表記が規格(SysML 2.0 の 9.2.20.1 節の表 34)で決められている 5 つのビューと、表のビューを、「ビュー」の選択欄で切り替えます。

| ビュー | 図 |
|---|---|
| 一般ビュー | 定義・使用と、その間の特殊化・型付けなどの関係の図(パッケージが直接持つ定義と使用と、その間の関係を描く) |
| 相互接続ビュー | 部品・ポート・接続の図。入れ子の箱、箱の縁のポート、入れ子をまたぐ線を描く |
| アクションフロービュー | 手順の図。行動・継承・フローと、部品ごとの列(swimlane) |
| 状態遷移ビュー | 状態機械の図。状態・遷移・`entry`・`do`・`exit` |
| シーケンスビュー | 部品の間のやりとりの図。頭・生存線・メッセージ |
| グリッドビュー | 4 つの表(部品の一覧、ポートと接続先、要求と満たす部品、機能の割り当て表) |

描く範囲:

- テキストに `view` があれば、`view` が `expose` で公開した要素のうち、`filter` の条件を満たすものだけを描きます。`expose X;` は X だけ、`expose X::*` は X の中の要素、`expose X::**` は X と、中を入れ子までのすべてです。
- `view` がなければ、アプリが範囲の候補(相互接続ビューなら、部品・ポート・接続を所有する部品の定義と使用など)を一覧にし、「範囲」で選びます。選んでもテキストは書き換えません。
- 「範囲」の選択欄の右の「view を書き足す」で、画面で選んでいる範囲を `view` 宣言としてテキストに書き足せます(書き足すのは、押したときだけです)。

グリッドビューの 4 つの表:

- 部品の一覧: 部品の使用(入れ子の部品を含む)ごとに、型・持ち主・多重度・説明(`doc`)
- ポートと接続先: 部品ごとのポート(型の定義から受け継いだものを含む)と向き・型、接続先(相手の部品.ポート)、つなぎ方(`connect`・`interface`・`flow`・`bind` など)。Arduino のピンの割り当て表に使える
- 要求と満たす部品: 要求の定義と使用ごとに、型・本文(`doc`)・満たす部品(`satisfy … by …`)・検証(`verify`)
- 機能の割り当て表: 行が行動、列が部品のマトリクス。`perform` か `allocate` で割り当てたものに印が付く

## 診断

左下の診断欄に、次のものを分けて出します。構文エラー・意味エラー・警告は、行と列を付けて出し、クリックするとテキストの該当箇所に移ります。

- **構文エラー**: テキスト表記として読めない箇所。直すまで、最後に正しく描けた図を薄く表示する。
- **意味エラー**: テキスト表記としては読めるが、SysML v2 の規則に反している箇所(名前が見つからない、区別できない名前、再定義の向きの食い違いなど)。規範に反することが、このアプリの持つ情報だけで確かめられるものに限る。図は描く。
- **警告**: 書き間違いのおそれがあるため、意図を確かめてほしい箇所。誤りとは限らない。W1 は使用の型の種類が合わないもの(例: `action def A; part p : A;`)、W2 は部品・ポートの使用で、型に書いた名前が使用の名前と同じもの(例: `part 'ブザー' : 'ブザー';`)。図は描く。
- **未検査**: 標準ライブラリの名前など、このアプリが中身を確かめていない名前。件数と、名前ごとにまとめた一覧で出す。
- **図の診断**: 描いていない要素(ほかのビューの要素、描く範囲の外に端のある接続など)や、反映していない `filter`・`render`。

「修正依頼をコピー」で、診断とテキストを、生成 AI に渡す修正依頼の文としてコピーできます。修正依頼の文に入る診断が 1 件もないときは、押せません。

## 図から編集する

図で要素を選ぶと、図の下の編集欄に、その要素の操作が出ます。

| 段階 | 図でできること | テキストの書き換え |
|---|---|---|
| 0 | 図の要素をクリックすると、テキストの該当箇所に移る | なし |
| 1 | 名前(と短い名前)を直す | 名前と、それを参照している箇所を置き換える |
| 2 | 部品・ポートを足す、相互接続ビューで接続を足す | 該当箇所に宣言を足す |
| 3 | 要素を削除する | 宣言を消し、一緒に消すもの(消す要素に端のある接続など)を、消す前に一覧で示す |

- 書き換えは構文木の範囲に限り、利用者のコメント・改行・記述の順を保ちます。
- 書き換えた後のテキストを解析し直し、意図した変更だけであることを確かめます。満たさなければ、書き換え前に戻して理由を表示します。
- 書き換える箇所や、書き換える名前を参照しうる箇所に、解決できない参照や曖昧な参照があるときは、操作を実行せず、理由を表示します。
- 1 回の操作は、テキスト欄の取り消し(Ctrl+Z)の 1 回で戻せます。

## フォルダで扱う

大きなシステムをファイルに分けて書けるよう、フォルダの中の `.sysml` をまとめて 1 つのモデルとして扱えます。ほかのファイルの要素を、名前や `import` で参照できます。

- 読み込み: 上の帯の「フォルダを開く」で選ぶか、フォルダを画面に置きます。フォルダの中の `.sysml` を、下のフォルダも含めてすべて読みます(名前が `.` で始まるフォルダの中は読みません)。`.sysml` が 1 つもないフォルダも開けます(フォルダの木から新しいファイルを作れます)。
- 木の欄: テキスト欄の左に、木の欄がいつもあります。フォルダを開いていないとき(1 つのファイルを開いているときを含む)は、「フォルダを開いていません」と「フォルダを開く」のボタンが出て、そこからフォルダを開けます(フォルダを木の欄に置いても開けます)。木の欄を畳んだかどうかは、ブラウザの中に覚えて、次に開いたときも同じにします。
- フォルダの木: テキスト欄の左に、フォルダの中のすべてのファイルとフォルダを出します(名前が `.` で始まるフォルダとその中は出しません)。各階層で、フォルダを先に、次にファイルを、名前の符号位置の順に並べます。幅は分割バーで変えられ、畳めます。上に、フォルダの名前と、新しいファイル・新しいフォルダ・再読み込み・すべて折りたたむ・木の欄を畳むのボタンがあります。
  - 今のファイルを木の中で強調し、テキスト欄の上に相対パスを出します。書き換えたまま保存していないファイルには印を付け、その印をフォルダにも伝えます。
  - `.sysml` のファイルをクリックすると、テキスト欄に出します。`.sysml` でないファイルは薄く出し、このアプリでは開きません(名前の変更・移動・削除はできます)。
- ファイルとフォルダの操作: 木の項目の右クリックで、新しいファイル・新しいフォルダ・切り取り・コピー・貼り付け・名前の変更・削除を出します。キーでは、F2 で名前の変更、Delete で削除、Ctrl+X・Ctrl+C・Ctrl+V で切り取り・コピー・貼り付けです。これらのキーが効くのは、「ファイル」の区画(下の「モデルツリーと参照箇所」の節)か、木の欄そのものに焦点があるときだけです(木の欄の上のボタンに焦点があるときも効きません)。「モデル」の区画と参照箇所の欄に焦点があるときは、これらのキーでファイルを操作しません(参照箇所の欄で文字を選んで Ctrl+C を押すと、その文字をコピーします)。ドラッグで、ファイルとフォルダをほかのフォルダに移せます。
  - 新しいファイル・新しいフォルダ・名前の変更では、木の中に名前の入力欄が出ます。Enter で決め、Esc でやめます。新しいファイルの中身は空で、拡張子は付け足しません(`.sysml` で終わる名前ならモデルに入り、テキスト欄に出ます)。
  - 名前は、空でないこと、`/`・`\`・`:`・`*`・`?`・`"`・`<`・`>`・`|` と制御文字を含まないこと、`.` で始まらないこと、末尾が `.` か空白でないこと、Windows の予約名(拡張子を除いた部分が `CON`・`PRN`・`AUX`・`NUL`・`COM1`〜`COM9`・`LPT1`〜`LPT9`。大文字・小文字を区別しない)でないこと、同じフォルダに同じ名前(大文字・小文字を区別しない)がないことが要ります。貼り付けで同じ名前があるときは、拡張子の前に「 のコピー」(さらに重なれば「 のコピー 2」…)を付けます。
  - Chrome・Edge でフォルダの扱いを得られたときは、操作をその場でディスクに入れます(最初の操作のときに、ブラウザが書き込みの許可を求めます)。それ以外のときは、操作をアプリの中だけで行い、「保存」の zip に入れます。
  - 削除では必ず確認が出ます。ブラウザから消したファイルは、ごみ箱に入らず、元に戻せません。
  - フォルダの名前の変更・移動・コピーは、新しい場所にすべてのファイルとフォルダを写し、すべての中身が同じことを確かめてから、元を消します(移動・名前の変更のとき)。途中で失敗したら元は消さずに止め、その操作で写す先に作ったもの(写し終えたファイルとフォルダを含む)をすべて消してから、理由を表示します。消せなかったものがあれば、それを理由に書き、木にも出します。
  - 書き換えたまま保存していないファイルを、名前の変更・移動・切り取りと貼り付けで動かしても、書き換えと取り消しの履歴は新しい相対パスのファイルに引き継ぎます(ディスクには、動かす前の保存した中身を写します)。
  - ファイルの操作は、テキストの取り消しの履歴に入りません。拡張子を `.sysml` に変えたファイルはモデルに入り、`.sysml` から変えたファイルはモデルから外れます。`.sysml` のまま名前を変えた・移しただけでは、モデルは変わりません(診断の相対パスだけが変わります)。
  - 再読み込み: フォルダの木をディスクから読み直します。再読み込みができるのは、フォルダの扱いを得られたとき(Chrome・Edge で、フォルダを選ぶ画面かドロップで開いたとき)だけです。書き換えていないファイルは中身を読み直します。書き換えたまま保存していないファイルは今のテキストを保ち、ほかで消えていたら木に残して印を付け、保存で作り直します。
- 取り消しとやり直しの履歴は、ファイルごとに持ちます(Ctrl+Z で取り消し、Ctrl+Y と Ctrl+Shift+Z でやり直し)。ファイルを切り替えても、ほかのファイルを書き換えても、前のファイルの履歴は失われません。
- 診断には、ファイルの相対パス・行・列を付けます。クリックすると、そのファイルに切り替えて該当箇所に移ります。
- 図からの編集は、書き換える箇所が複数のファイルにまたがるものも行い、1 回の取り消しで、すべてのファイルについて戻します。
- 保存: Chrome・Edge では、「保存」で、書き換えたファイルだけを、読み込んだフォルダの同じ相対パスに上書きします(最初の上書き保存のときに、ブラウザが書き込みの許可を求めます)。フォルダの扱いを得られないとき(ほかのブラウザなど)は、フォルダの木のすべてのファイル(`.sysml` でないものは中身をそのまま)と空のフォルダを、相対パスのまま入れた zip を保存します。
- パッケージに、標準ライブラリの根の名前空間と同じ名前(`Parts`・`Items`・`Ports` など)を付けないでください(ほかのファイルから指すと、標準ライブラリのものと区別できず曖昧になります)。

## モデルツリーと参照箇所

大きなモデルをファイルに分けて書くとき、定義と使用の所属と参照を見渡し、目的の記述へ移るためのものです(VS Code のエクスプローラーとアウトラインに倣っています)。1 つのファイルのときも、フォルダのときも出します。

- 置き場所: テキスト欄の左の木の欄を、上の「ファイル」(フォルダの木)と下の「モデル」(モデルツリー)の 2 つの区画に分けます。区画はそれぞれ見出しの行で畳めます。畳んだかどうかは、区画ごとにブラウザの中に覚えます。「モデル」の区画の下に「参照箇所」の欄があります。木の欄そのものを畳む(「木の欄を畳む」のボタン)と、両方の区画をまとめて畳みます。「モデル」の区画と参照箇所の欄に焦点があるときは、F2・Delete・Ctrl+X・Ctrl+C・Ctrl+V でファイルを操作しません(参照箇所の欄で文字を選んで Ctrl+C を押すと、その文字をコピーします)。
- 区画の高さ: 分割バーは 2 つあります。区画の境目の分割バーで「ファイル」と「モデル」の区画の高さを、モデルツリーと参照箇所の欄の境目の分割バーで参照箇所の欄の高さを変えられます。初めは、フォルダを開いていないときは「ファイル」の区画を中身(「フォルダを開いていません」の形)の高さだけにして、残りを「モデル」の区画に使います。フォルダを開いているときは、「ファイル」の区画を木の欄の高さの 40%、「モデル」の区画を 60% にします。参照箇所の欄は、初めは「モデル」の区画の高さの 40% です。分割バーで変えた高さは木の欄の高さに対する割合で持ち、窓の大きさが変わったとき、フォルダを開いた・閉じたとき、木の欄の上の帯の高さが変わったときに、その割合から付け直します。どの区画と欄にも最小の高さ(区画 60px、モデルツリー 40px、参照箇所の欄 56px)を残し、窓を縮めても、区画・欄・分割バーを木の欄の外に出しません(足りない分は、区画の中のスクロールで見せます)。分割バーで変えた高さは、ブラウザの中に覚えません。
- 並べるもの: 読み込んだファイルの要素だけを並べます(標準ライブラリの要素は並べず、型として名前だけを出します)。根は大域の名前空間で、各ファイルの根の要素(パッケージなど)を、ファイルの並びの順、ファイルの中は記述の順に並べ、その下に持ち主の所有するメンバーを記述の順に並べます。フォルダの木とは別のもので、ファイルの境目は木の形に出しません。パッケージ、すべての種類の定義と使用と、名前がなくても構成をたどるのに要る要素(遷移・継承・接続・結合・流れ・`perform`・`exhibit`・`satisfy`・`send`・`accept`・`assign` など)を並べ、`import`・注釈・`doc`・式・値の中身は並べません。`send`・`accept`・`assign` などの行動の引数(送るもの・宛先・経由など、名前を宣言していない引数)、式を値に持つだけの名前のない特徴(名前のない列挙の値 `enum = 60 [mm];` を含む)、名前のない特徴の連鎖も並べません。
- 項目の表示: 定義か使用かの印(定義は四角に「定」、使用は丸に「使」。文字の色だけに頼らず、形で見分けられます)、名前(引用符を外します。名前がない要素は、種類とたどる相手の名前の要約。例: 遷移なら「遷移 A → B」、送信なら「送信 Sig → 宛先」、代入なら「代入 対象」。接続・流れ・結合などの要約では、端の名前を連鎖(`a.b`)を含めて全部出します)、使用に明示した型と多重度(`: T [1..*]`)、種類の順に並べます。幅が足りないときは、まず種類を、次に型と多重度を、省略の記号を付けて切ります(名前はなるべく残します)。ただし、型を出す項目では、型を押せるよう、型と多重度に 3 文字ほどの幅を残し、名前が長いときはその分だけ名前を切ります。マウスを載せると、修飾名・種類・型と多重度・ファイルの相対パスと行を出します。名前がない要素の修飾名の区切りは、その要素の要約をかっこで囲んで書きます(例: 「懐中電灯の部品::Flashlight::(接続 電池.正極 – スイッチ.入口)」)。要約がないときだけ「(名前なし)」と書きます。同じ名前の別の要素は、持ち主の違いと、マウスを載せたときの修飾名・ファイルで見分けられます。
- 型の表示と移動: 使用の型を押すと、型の定義へ移ります。型が 2 つ以上なら、型の一覧を出して選ばせます(一覧は、解析し直したときと木を作り直したときに閉じます)。標準ライブラリの型には「(標準ライブラリ)」を添え、移りません。未検査・曖昧の型は、その状態の印を付けて出し、押しても移りません。
- 参照箇所: モデルツリーで選んだ要素(定義・使用・パッケージ)に解決している参照を、すべてのファイルから集めて出します(型付け・特殊化・再定義・部分集合・参照・接続や結合や流れの端・遷移の元と先・継承の元と先・`perform`・`exhibit`・`include`・`satisfy`・`send`・`accept`・`import` など)。役割ごとにまとめて件数を見出しに出します。`send` の参照は送るもの・宛先・経由を、`accept` の参照は受け取る型・経由を、別の役割にします。修飾名の途中の区切り(`P::X` の `P`)は「修飾名の区切り」の役割です。行は 2 段で、上の段に役割の印と所属(参照している要素の修飾名。名前がない要素の区切りは、上の「項目の表示」と同じ書き方)、下の段にファイルの相対パスと行を出します(所属が長いときは、先頭を省略の記号にして末尾を残します。マウスを載せると全部を出します)。未検査・曖昧の参照は、どの要素の参照箇所にも入れません。
- 移動: モデルツリーの項目と参照箇所の行を押すと、その要素(参照箇所の行では、その参照の名前)が書かれているファイルを表示し、その箇所までテキスト欄を送り、字句を選びます。選ぶ字句は、名前を宣言した要素ではその名前の字句、名前を宣言せずに参照する名前を項目の名前として出す要素(`perform drive;`・`exhibit st;`・`include uc;`・`attribute :>> '光量';` など)ではその参照の名前の字句、それ以外の名前がない要素では宣言の始まりの字句(`entry;` では `entry`、`then s1;` では `then`、遷移では `transition` など)です。選んだ字句がテキスト欄の見える範囲に入るよう、縦と横に送ります(字句がすでに見えていれば横の送りは変えず、見えていなければ、字句の始まりを見える幅の左から 4 分の 1 に置きます)。診断のクリックで移るときも同じです。別のファイルへ移るときも、保存していない書き換えと取り消しの履歴を保ちます。移った後、「ファイル」の区画でもそのファイルを強調します。
- 開閉と選択: 根の要素は開き、それより下は閉じた状態で始めます。解析し直した後も、同じ要素(ファイルの相対パスと修飾名と、同じ修飾名の中の記述の順で同じとみなす)の開閉と選択を保ちます。名前を変えた要素は別の要素として扱います(選択が外れ、参照箇所の欄は空になります)。参照箇所の欄で選んだ要素がなくなったときは、欄を空にします。
- 古い解析: テキストを書き換えてから解析が終わるまでの間は、モデルツリーと参照箇所を「解析し直しています」の印を付けて薄く出し、押しても移りません。構文エラーのあるファイルは、そのことを区画の上に出し、そのファイルの要素は出しません。名前の変更・追加・削除・ファイルの操作・再読み込みの後も、解析し直した結果で作り直します。

## 保存と読み込み

| 形式 | 扱い |
|---|---|
| `.sysml` | 正本。「保存」で、テキストをそのまま保存する。アプリ固有の情報を書き込まない。開いたファイルの改行の形(LF・CR LF・CR)で保存する |
| `.svg` | 図・表 1 つずつの画像。テキスト(原文)は埋め込まない |
| `.png` | 図・表 1 つずつの画像(2 倍の解像度) |
| PDF | 図・表 1 つずつを、同じ大きさの紙(余白 0)でブラウザの印刷にかける。印刷の画面で「PDF に保存」を選ぶ |
| タブ区切りの文字 | 表をクリップボードに写す(表計算ソフトや Word の表に貼れる)。`=`・`+`・`-`・`@`・`"` で始まるセルは、先頭に `'` を付ける |

- 「開く」とドラッグ・アンド・ドロップで読み込めるのは `.sysml` だけです。2 つ以上のファイル・フォルダを一度に置いたときは、どれも読み込みません。
- テキストを書き換えた後に「開く」「フォルダを開く」「新規」「例を読み込む」やドロップをすると、置き換えてよいかを確かめます。
- 図は図の上の「SVG」「PNG」「PDF」、表は表の題の右の「コピー」「SVG」「PNG」「PDF」で、1 つずつ保存します。ファイル名は、図は「元の名前_ビュー_範囲の名前」、表は「元の名前_grid_表の題」です。

## 報告書に載せる

- TeX: 図・表の「PDF」で作った PDF を貼ります(紙の余白は 0 です)。
- Word・スライド: 図・表の「SVG」か「PNG」で保存して貼ります。表は「コピー」で、Word の表に貼ることもできます。
- 表の画像には題を入れません。図の画像には、左上に名前のタブが入ります。

## 動作環境

ブラウザだけで動きます(Node.js は、ビルドと検査にだけ使います)。ネットを切った状態でも、`index.html` を `file://` で開いて、解析・描画・保存ができます。

- フォルダを選ぶ画面と、フォルダへの上書き保存は、Chrome・Edge で使えます(File System Access API)。ほかのブラウザでは、フォルダを選ぶ欄で読み込み、zip で保存します。
- 図・表の「PDF」は、Chrome・Edge で使ってください。

## 規格とパイロット実装との差

基準とする規格は、SysML 2.0 正式版(formal/2026-03-02)と KerML 1.0 正式版(formal/2026-03-01)です。公式リポジトリ SysML-v2-Release のタグ 2026-03 が、この版に対応します。

- パーサーは、仕様書本文の文法を表として持ち、Earley 法で解釈します。本文の文法の誤りは、2.1 Beta 2 の本文に課題番号付きで示された修正で直し、2.1 Beta 2 にも修正がない箇所だけ、パイロット実装(SysML-v2-Pilot-Implementation、タグ 2026-03)の文法を根拠に手当てします(57 件)。
- 名前解決は、KerML 1.0 の 8.2.3.5 節に従います。標準ライブラリのファイルは同梱せず、名前解決に要る名前と関係だけを抜き出した索引を内蔵します。索引にない名前への参照は、エラーにせず「未検査」とします。
- 公式の例題(251 ファイル)と標準ライブラリの `.sysml`(58 ファイル)の計 309 ファイルについて、受理・拒否、構文木、名前解決、意味エラーをパイロット実装と照合しています。

本文に従った結果、パイロット実装と受理・拒否や名前解決の結果が食い違う箇所(たとえば、単一引用符の名前の中のタブ・改行は使えない、エスケープ列 `\r` は使えない、ほかのファイルの根の名前空間の `private` の要素は見えない)の一覧は、設計書 `docs/design.md` の 2.5 節にあります。図表記で本文から外れる点は 7.8 節にあります。

## 開発(ビルドと検査)

ビルドと検査は、外部のパッケージを使わない Node.js のスクリプトで行います。`src/` のコードは、Node.js 固有の機能を使いません。

ビルド:

```
node tools/build/build.mjs            # index.html と docs/prompt_for_ai.md を作り直す。相互接続ビューだけの HTML を out/build/ に出す
node tools/build/build.mjs --check    # あわせて、2 回のビルドが同じバイト列になること、外部の読み込みがないことを確かめる
```

`index.html` は直接直さず、`src/` を直してビルドで作り直します。同じソースからは同じバイト列ができます。

検査:

```
node tests/parser/run.mjs
node tests/model/run.mjs --skip-pilot
node tests/view/run.mjs
node tests/semantic/run.mjs --skip-pilot
node tests/edit/run.mjs
```

検査の前に、次のものを用意します。

1. `bash tools/fetch.sh`: 公式のファイルを GitHub から `vendor/` に取得します(SysML-v2-Release のタグ 2026-03 の例題・標準ライブラリ・文法・仕様書の PDF、タグ 2026-08 の仕様書の PDF、SysML-v2-Pilot-Implementation のタグ 2026-03)。`git` と `pdftotext` を使います。取得の記録を `reports/GR1/` に書きます。
2. `node tools/build/prepare_check.mjs`: ネットワークの要らない前提を `out/` に作ります(309 ファイルの一覧 `out/files309.txt`、仕様書のテキスト `out/text/`、色付けの時間を測る大きな入力 `out/view/big.sysml`、変異ファイル `out/mutation/`)。終わりに、前提があるかないかの一覧を出します。
3. パイロット実装の結果(`out/pilot/files309`・`out/pilot/mutation`・`out/pilot/resolve`・`out/pilot/resolve_cases`・`out/pilot/validate`・`out/pilot/validate_cases`・`out/GR20/pilot`): parser・model・semantic の検査が、パイロット実装との照合に使います。パイロット実装の jar(`vendor/pilot/org.omg.sysml.interactive/target/org.omg.sysml.interactive-0.58.0-SNAPSHOT-all.jar`)を `vendor/pilot` で `./mvnw clean package -DskipTests` でビルドし(Maven と依存のライブラリを GitHub の外から取得します。Java が要ります)、実行器 `tools/pilot-runner/src/` で作ります。
   - `out/pilot/resolve`・`out/GR20/pilot` は `node tests/model/run.mjs`、`out/pilot/validate`・`out/pilot/validate_cases`・`out/pilot/resolve_cases` は `node tests/semantic/run.mjs`(どちらも `--skip-pilot` を付けない)が、jar で作り直します。
   - `out/pilot/files309`・`out/pilot/mutation` は、実行器 `PilotRunner` で作ります(使い方は `tools/pilot-runner/src/PilotRunner.java` の冒頭)。
   - 別の木にパイロット実装の結果があるときは、`node tools/build/prepare_check.mjs --pilot-from <その木>` で、その木の `out/` から写せます。
